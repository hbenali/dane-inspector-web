DANE TLSA inspect & match

See which certificate a host pins in DNS, whether DNSSEC vouches for it, and whether your certificate matches.

Look up TLSA records

DANE (RFC 6698, RFC 7671) publishes a hash of a server's certificate or key in a TLSA record, so clients need not trust a public CA. For email it is profiled in RFC 7672. It is only meaningful when the DNS answer is DNSSEC-validated.

mail mode finds the MX records, then the TLSA record at _25._tcp.<mx-host>
TLSA name is _<port>._tcp.<host> (443 for HTTPS, 25 for SMTP, 465/587 for submission)

Match a certificate

Paste one or more PEM certificates. The page hashes them with WebCrypto in your browser and compares the result with the TLSA records of the last lookup. The certificate is never uploaded.

What this page cannot do

  • noteA browser cannot open a TCP connection, so it cannot fetch the live certificate a server presents. Paste the PEM yourself (for example from openssl s_client -connect host:25 -starttls smtp).
  • noteThe DNSSEC verdict is the resolver's: the AD flag from dns.google. This page does not validate signatures itself.
  • noteMatching compares hashes only. It does not validate the certificate chain, names or expiry.
